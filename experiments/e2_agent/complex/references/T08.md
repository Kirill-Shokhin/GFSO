## Task `T` (verbatim, PLAN §3 T08)

> Design the end-to-end logic of a compiler front-end for a small statically-typed language:
> lexing, parsing, name/scope resolution, type-checking, lowering to a typed intermediate representation
> (IR), and code generation. Specify the **contract each stage must satisfy for the next** so the produced
> code is well-formed.

**Shape.** Chained pipeline: source text → lexer → parser → name/scope resolver → type checker → IR lowering
→ code generation. The load-bearing content is the **exact, decidable inter-stage contracts** (each stage's
output is the next stage's input, each contract individually falsifiable) and the **pipeline-wide invariants**
no single stage can establish (every node typed before lowering; source positions preserved end-to-end; no
pass invalidates a prior pass's invariant). Achievement goal: a correct connective design that *terminates*
in well-formed produced code — not a maintenance regime.

**Defect-class (distinctness from T02, the other chained-pipeline task).** T02's inter-stage contracts are
**statistical/data** (distribution skew, leakage — probabilistic, monitored, never provably absent). T08's
are **exact formal contracts** (well-typedness, grammar-conformance, every-name-bound — decidable, provable
per compilation). The same seam is *checked*, not *estimated*: a violation is a compiler bug an arbitrary
input can exhibit, not a drift to monitor. This is the high-decidability end of the dataset.

**Single meta-level.** This decomposes one front-end's **logic** at one level: the passes and the contracts
between them. It does NOT spawn sub-projects (write a parser generator, build a register allocator, port a
backend, design the source language). Components are passes of one design, not deliverables owned by
different teams. (Consequence: the OPERATIONAL failure modes {FM-5,6,7} — runtime/execution-time modes — are
mostly out of scope for this static single-meta-level decomposition; see §7.)

**Scope anchor (the `spec`).** The two halves of the goal `spec` are: (a) **each stage satisfies the exact
contract the next stage relies on** (the `Dep`-seams) and (b) **the produced code is well-formed** (the
pipeline-wide invariant criteria — well-typed throughout, positions preserved, no construct dropped, no
invariant invalidated downstream). A decomposition is complete iff it covers both halves.

## 1. Subtasks `D` — the front-end passes (the parts)

> `D` = the children of the decomposition (canon §2.2: `D: T → P(T)`, a DAG).

Each subtask is a **pass**: a separable stage with its own pass/fail criterion on its *output artifact* (a
token stream, a parse tree/AST, a resolved AST with a symbol table, a typed AST, a typed IR, target code),
not a self-report ("parser written"). The richness of T08 is in the **exact contracts between** these passes
(`Dep`) and the **pipeline-wide invariant criteria** (§4), so `D` is the saturated, recall-friendly backbone;
the discriminating content lives in `Dep` and the criteria. Source-position tracking and the diagnostics/error
channel are **cross-cutting concerns of every pass**, not standalone passes — they are scored as criteria
(V-I4) and a seam (Dep9), to keep the design at one meta-level (mirrors T07's treatment of concurrency
control).

| # | Name | What it requires | Truth-maker (covered iff the decomposition names…) |
|---|---|---|---|
| **D1** | **Lexer / scanner (tokenizer)** | Converts the raw character stream into a stream of tokens (keywords, identifiers, literals, operators, punctuation), classifying lexemes; each token carries its source span. Defines the lexical grammar and the maximal-munch / longest-match rule, and a **fixed total trivia rule**: whitespace/comments are *either* discarded *or* attached as trivia by one definite rule, so the parser never sees raw trivia as a significant token. | …a lexing/tokenizing pass that turns characters into a token stream (lexemes classified into token kinds) with a definite trivia rule (whitespace/comments dropped-or-attached, never surfaced to the parser as a real token). Credit "lexer," "scanner," "tokenizer," "split source into tokens," "skip whitespace/comments." The pass everything downstream consumes. |
| **D2** | **Parser (syntactic analysis → AST)** | Consumes the token stream and, per the language's context-free grammar, builds a structured tree (parse tree / abstract syntax tree) representing the program's syntactic structure; rejects token sequences not in the grammar with a syntax error. Defines the grammar, precedence/associativity, and the AST node shapes. | …a parsing pass that consumes tokens and produces an AST/parse tree per the grammar (and rejects ill-formed syntax). Credit "parser," "build the AST," "syntax analysis," "recursive-descent / LR parse." The structural backbone the later passes walk. |
| **D3** | **AST / IR data model (the tree + node definitions)** | The concrete data structure the passes share: the AST node types (expressions, statements, declarations, types) and, downstream, the typed-IR node types — the in-memory representation every pass reads and annotates (with slots for resolved bindings, inferred types, source spans). | …the AST/node-type definitions or the intermediate data model the passes operate on (expression/statement/decl node kinds, the tree the passes annotate). Credit "define the AST," "node types," "the tree representation," "the IR data structures." Distinct from D2 (D2 = the *act* of parsing; D3 = the *data model* parser and all later passes share). An agent may fold D3 into D2/D5 explicitly — credit both if they define the node types as part of naming parse/lowering. |
| **D4** | **Name / scope resolution (binding)** | Walks the AST and binds every identifier use to its declaration, building and consulting a **symbol table** with lexical **scopes** (nested blocks, function/parameter scopes, module/global scope, shadowing rules); reports unbound names and (per the language) duplicate/conflicting declarations. Establishes the def→use links the type checker needs. | …a name-resolution / binding pass with a symbol table and lexical scopes that links each name use to its declaration (and errors on unbound names). Credit "scope resolution," "name binding," "symbol table," "resolve identifiers to declarations," "build scopes." The pass the type checker's lookups rest on. |
| **D5** | **Type checker (semantic analysis, incl. control-flow static checks)** | Walks the resolved AST and checks the language's typing rules: assigns/infers a type to every expression, checks assignability/compatibility at every use (operators, calls, assignments, returns, conditions), and rejects ill-typed programs with a type error. Also performs the standard **control-flow static-semantic checks** the type system implies: **return-path completeness** (a non-void function whose every path must return is diagnosed if some path falls off the end), **definite-assignment** (no read of a possibly-unassigned variable), and a stated **unreachable/dead-code** policy. Produces a **typed AST** (every node annotated with its type). | …a type-checking / semantic-analysis pass that assigns types and rejects type errors (every expression typed, every use checked) **and** performs the flow-sensitive static checks — return-on-all-paths, definite-assignment, dead-code policy. Credit "type checker," "semantic analysis," "infer/check types," "reject ill-typed programs," "missing return on a path," "use before assignment." The pass that makes "statically typed" real; produces the typed tree IR lowering consumes. |
| **D6** | **IR lowering (lowering the typed AST to a typed IR)** | Translates the typed AST into a lower-level **typed intermediate representation** (e.g. a typed CFG / three-address / SSA-ish form): desugars high-level constructs (loops, pattern/match, short-circuit operators) into the IR's primitive set, **carrying type information onto every IR node** and lowering each source construct to a semantically-equivalent IR fragment. | …a lowering / IR-generation pass that translates the typed AST into a (typed) intermediate representation, desugaring high-level constructs. Credit "lower to IR," "generate IR," "desugar," "translate AST to the intermediate form." Distinct from D5 (D5 = check types; D6 = *emit the IR* carrying those types). |
| **D7** | **Code generation (lowering IR → target code)** | Emits the target code (target instructions / bytecode / a lower IR) from the typed IR — the front-end's final output artifact. Within this design's scope: the *structural lowering* of each IR construct to a target form (control flow, calls, data layout at the model level). Optimization passes and full target back-end concerns (register allocation, instruction scheduling, ABI/calling-convention realization) are **out of scope** (N1/N2) — this is the front-end's hand-off, not a full back-end. | …a code-generation / emission pass that produces target code (or bytecode / lower IR) from the IR. Credit "codegen," "emit instructions/bytecode," "generate target code," "lower IR to target." The terminal pass; its well-formedness is the goal `spec`'s endpoint. |

> **Note on `D` granularity.** Lexer (D1) and parser (D2) are kept distinct (token contract vs grammar
> contract — distinct truth-makers, an agent can name one without the other). Name resolution (D4) and type
> checking (D5) are kept distinct on purpose: resolution binds *names* (def→use), type-checking checks
> *types* — different errors, different tables, and the resolution→typecheck handoff is the Dep4 seam.
> Folding them into one "semantic analysis" pass that *explicitly* does both binding and typing covers D4,
> D5 **and** the Dep4 seam in one stroke (credit all three); a "semantic analysis" that names only type rules
> has D5 but not D4/Dep4. D3 (the AST/IR data model) is listed because the *shared node definitions* are a
> real artifact every pass depends on (the `Dep`-seams are contracts *on this artifact*); an agent who defines
> node types while naming the parser/lowering covers D3.

## 2. Dependencies `Dep` — cross-stage contracts as explicit, separately-falsifiable `Dep` edges

> `Dep` = the canon primitive (§2.2): an acyclic relation on `T × T`; `(tₐ, tᵦ) ∈ Dep` iff `criteria(tᵦ)`
> references the output of `tₐ` (with coherence `deadline(tₐ) < deadline(tᵦ)`). **Each `Dep` edge is a
> criterion of a child that references a sibling's output — the glue** — and carries its **own** decidable
> falsifying truth-maker (the anti-mock condition), not "these stages relate" prose.

**The dominant and most-forgotten category — the heart of T08 (PLAN: "rich in EXACT inter-stage
contracts").** Each seam is a REAL edge: the *output artifact of one named stage feeds the input of
another*, and the edge carries its **own** decidable falsifying criterion — a concrete program (or program
fragment) for which, if the contract is loose, the front-end produces a wrong or ill-formed result
(Constitution Ст. II.5 anti-mock). Not "these stages relate" prose. A seam is covered iff the decomposition
names the **same ordered stage pair** and the **same thing that breaks** if the contract is absent/loose.
The shared artifact (the token stream, the AST shape, the symbol table, the type annotations, the IR, the
source span) is named in each row — a forgotten contract here is an objectively identifiable **compiler
bug**. **One-defect-one-place:** each `Dep` is a contract with its own breakage; a defect-coupling criterion
(§4.3) is kept only if it has NO `Dep`-twin.

| # | Name | Pair (producer → consumer) | What the contract requires | Truth-maker (covered iff named with its breakage) |
|---|---|---|---|---|
| **Dep1** | **Token-stream contract (lexer → parser)** | D1 → D2 | The lexer emits a well-formed token stream the parser's grammar is defined over: every lexeme classified into exactly the token kinds the grammar expects, maximal-munch resolved (e.g. `>=` is one token not two; `1.0e-3` one number), and a definite end-of-input token. The parser may assume token kinds and boundaries, never re-scan characters. | …that the lexer's output token kinds/boundaries are exactly the alphabet the parser's grammar consumes (the parser parses *tokens*, not characters), and a mis-tokenization (wrong munch, wrong kind) propagates a spurious syntax error. Shared artifact = the token stream. Credit "the parser consumes the lexer's tokens and relies on their kinds." |
| **Dep2** | **AST-shape contract (parser → consumers)** | D2 → D3/D4/D5 | The parser produces a tree of exactly the node shapes the downstream passes expect to walk — the AST grammar (which nodes have which children, how precedence/associativity are encoded into tree structure). Resolution and type-checking pattern-match on this shape; a parser that builds a differently-shaped tree (or omits a node the checker expects) silently breaks the consumer. | …that the parser's AST node shapes are exactly what resolution/type-checking walk (a fixed AST contract: node kinds + child structure + encoded precedence), and a shape mismatch (missing/misshaped node) breaks the downstream pass. Shared artifact = the AST node structure (D3). Credit "the AST shape the later passes rely on." |
| **Dep3** | **No-construct-dropped contract (parser → lowering, end-to-end coverage)** | D2 → D5 → D6 → D7 | Every surface construct the grammar accepts must be *handled* by every later pass — resolved, typed, lowered, and code-generated. A construct the parser accepts but a later pass has no case for (silently skipped, or a `TODO`/default branch that drops it) yields missing or wrong output for a valid program. The contract: the set of node kinds the parser can produce ⊆ the set each later pass handles. | …that every construct accepted by the parser must be handled by resolution, typing, lowering AND codegen (no accepted construct silently dropped before output) — a parse-but-don't-lower gap is a real bug. Shared artifact = the node-kind coverage set across passes. Credit "every syntactic form must be lowered/codegen'd, not dropped." **Easily-forgotten cross-pass contract** — distinct from any single adjacent edge. |
| **Dep4** | **Resolution → type-check contract (binding info the checker relies on)** | D4 → D5 | The type checker assumes every identifier in the AST has already been bound to a declaration (a symbol-table entry with the declaration's type) — its type rules look up the *declared* type of a name. If resolution is incomplete (a name left unbound) or wrong (bound to the wrong scope/shadowed decl), the checker either crashes on a null binding or assigns the wrong type. The contract: resolution completes and every use carries a valid binding before typing. | …that type-checking depends on resolution having bound every name first (the checker reads declared types via the symbol table), and an unresolved/mis-resolved name produces a wrong/absent type. Shared artifact = the symbol table / def→use links. Credit "the type checker uses the resolved bindings / symbol table." **Defining semantic seam.** |
| **Dep5** | **Scope/symbol-table contract (resolver ↔ type-checker shared scopes)** | D4 ↔ D5 | Resolution and typing must agree on the **same** scoping discipline: the scope in which a name is resolved must be the scope whose declared type the checker uses (block scope, shadowing, capture). If the resolver binds in one scope model and the checker assumes another, shadowing/capture bugs let a use see the wrong declaration's type. (Tie to Dep4: Dep4 is *that bindings exist*; Dep5 is *that the two passes share one scope/shadowing semantics*.) | …that resolution and type-checking share one consistent scope/shadowing model (a name's resolved declaration and its type come from the same scope), and a divergence yields a shadowing/scoping type bug. Shared artifact = the scope structure + shadowing rules. Credit "consistent scoping between binding and typing." Distinct from Dep4 (existence of binding) — this is *agreement on the scope semantics*. |
| **Dep6** | **Every-node-typed contract (type-checker → lowering)** | D5 → D6 | IR lowering consumes a **fully-typed** AST: every expression/sub-expression node carries its checked type, because lowering's translation choices depend on type (overload resolution, numeric width, dispatch, coercions/box-unbox, which IR op to emit). An untyped or partially-typed node forces lowering to guess or emit a wrong/untyped IR fragment. The contract: type-checking annotates every node lowering will read. | …that lowering requires every AST node to be already typed (type-directed lowering: the type chooses the IR op/coercion), and a missing type annotation breaks/mis-lowers the node. Shared artifact = the per-node type annotations on the typed AST. Credit "lowering uses the inferred types," "IR generated from the typed tree." **The seam V-I3 (every IR node well-typed) rests on.** |
| **Dep7** | **IR well-formedness contract (lowering → codegen)** | D6 → D7 | Code generation consumes a **well-formed, type-consistent** IR: each IR instruction's operands have the types it expects, control flow is structurally valid (every block terminates, no use-before-def, the CFG is connected), and the IR's invariants (SSA dominance if SSA, typed operands) hold. Lowering that emits a malformed IR (mistyped operand, dangling block, use-before-def) makes codegen emit wrong code or crash. The contract: lowering's output satisfies the IR's well-formedness predicate codegen assumes. | …that codegen relies on the IR being well-formed and type-consistent (valid operands, terminated/connected control flow, no use-before-def), and a malformed IR breaks codegen. Shared artifact = the typed IR + its well-formedness invariant. Credit "the IR codegen consumes must be well-formed / type-consistent." |
| **Dep8** | **Semantic-checks-complete-before-lowering contract (gate seam)** | D5 → D6 | Lowering (and codegen) must run **only after** all semantic checks pass — an ill-typed (or unresolved) program must be *rejected*, never lowered. If the pipeline lowers a node that failed (or skipped) type-checking, an ill-typed program reaches codegen and produces unsound output (the "ill-typed IR escapes" failure). The contract: a failing semantic phase halts the pipeline before IR is generated for the offending program. | …that lowering is gated on type-checking succeeding (no IR is generated from an un-typechecked / type-error node; an ill-typed program is rejected, not compiled). Shared artifact = the pass-ordering gate (semantic verdict → permission to lower). Credit "don't generate IR for an ill-typed program," "type errors stop compilation before codegen." **The ordering seam that keeps the front-end sound** — most-forgotten as an explicit *edge* (agents assume it implicitly). |
| **Dep9** | **Source-position propagation contract (span threaded through every stage)** | D1 → D2 → D4 → D5 → D6 (→ diagnostics) | Each pass must **carry the source span** from its input artifact onto its output artifact so that an error or diagnostic raised by *any* pass (or by a tool consuming the IR) can point back to the originating source location. The contract is an edge on *every* stage boundary: the lexer attaches spans to tokens, the parser copies them onto AST nodes, resolution/typing attach them to errors, lowering keeps them on IR nodes. A pass that drops the span yields a diagnostic with no/wrong location. | …that source positions/spans are threaded from the lexer through every later pass onto AST/IR nodes and onto diagnostics (so any stage's error can point at the source), and a dropped span yields a useless "error somewhere" diagnostic. Shared artifact = the source span travelling on each node/token. Credit "track source locations through the passes for error messages." **Classic forgotten cross-stage contract** — the per-stage version of invariant V-I4. |
| **Dep10** | **Error-recovery / error-propagation handoff (one pass's errors → next pass's behavior)** | D2 ↔ D4/D5 (and D1 ↔ D2) | When a pass detects an error, it must hand a defined state to the next pass: either **stop** (don't run typing on an unparseable tree) or insert an **error/poison node** that downstream passes recognize and skip — so one error doesn't cascade into a flood of spurious secondary errors, and a later pass never treats an error placeholder as a real node (e.g. type-checks a syntactically-broken subtree). The contract: the producer marks errors in the artifact and the consumer's contract covers the error markers. | …that an error in an earlier pass is handed to the next pass in a defined way (stop, or poison/error nodes the consumer skips) so errors don't cascade into spurious downstream errors / a later pass doesn't process a broken node as valid. Shared artifact = the error markers / recovery state in the AST. Credit "error recovery so one error doesn't produce a cascade," "synchronize and continue," "poison nodes." Distinct from Dep9 (Dep9 = *location* of an error; Dep10 = *handoff of the error state* between passes). |
| **Dep11** | **Symbol-allocation contract (resolver/checker decl ↔ IR-gen symbol)** | D4/D5 → D6 | Each AST declaration the resolver bound (and the checker typed) must lower to **exactly one** IR symbol / storage slot, and **every** use of that name must lower to a reference to *that same* symbol — no declaration collapses with another (two decls → one slot, aliasing distinct names), no declaration yields two slots (a use binds to the wrong copy), and no IR reference is **dangling** (a use whose declaration was never allocated a symbol). The contract: lowering walks the resolved def→use links and allocates a stable, unique IR symbol per declaration that all its uses share. | …that resolution/typing's bindings lower to a *one-declaration-↔-one-IR-symbol* mapping where every use references that symbol and no IR symbol is dangling/collapsed/duplicated (each declared name gets one IR storage location/slot the lowerer reuses for all its uses). Shared artifact = the AST-decl ↔ IR-symbol map (the resolved def→use links *carried into* the IR). Credit "each declaration becomes one IR slot/register/symbol all its uses point at." **Distinct from Dep4** (Dep4 stops at the checker — bindings *exist*; Dep11 is the *binding → IR-symbol* lowering edge) **and from Dep7** (Dep7 is IR-internal well-formedness; Dep11 is the *source-decl-to-IR-symbol faithfulness* across the D5→D6 boundary). |
| **Dep12** | **Type-mapping contract (checker type-system ↔ IR type-system across the boundary)** | D5 → D6 | The source-level type system and the IR-level type system must be a **faithful image**: `lowerType(checker_type)` is a **total** function (every checker-legal type has a defined IR type — no construct types-check but has no IR type), every coercion the checker *accepted* (implicit numeric widening, box/unbox, subtype-to-supertype, nullable) lowers to a **legal, explicit IR conversion** (no coercion silently dropped or made into an invalid IR cast), and subtyping/assignability decisions **agree across the boundary** (what the checker calls assignable the IR also accepts). A gap makes lowering emit an IR fragment whose types the IR's own rules reject (or, worse, accept wrongly). | …that the checker's type system maps *totally* onto the IR type system, every checker-accepted coercion has a corresponding legal IR conversion, and subtyping/assignability agree across the D5→D6 boundary (the source and IR type systems are consistent images of each other). Shared artifact = the source-type→IR-type map + the coercion/assignability correspondence. Credit "lowering maps each source type to an IR type and turns implicit coercions into explicit IR conversions, consistently." **Distinct from Dep6** (Dep6 = the *annotations are present* / never re-infer; Dep12 = the *type systems are consistent* — a node can carry its source type yet have *no legal IR type*) **and from Dep7** (Dep7 = the IR is internally consistent given its operands; Dep12 = the *source↔IR type correspondence* that makes those operands right in the first place). |

> **Anti-mock note.** Every `Dep` references a concrete *shared artifact* (the token stream, the AST node
> shape, the symbol table, the per-node type annotations, the IR + its well-formedness predicate, the source
> span, the error markers) — a forgotten contract here is an objectively identifiable **compiler bug** (a
> spurious error, a wrong type, an ill-typed IR, a useless diagnostic, an error cascade), not a nominal pair.
> None collapse onto each other: different stage pair OR different falsifier ⇒ distinct seam (PLAN §1.3 rule
> 1). In particular Dep4 (bindings *exist*) ≠ Dep5 (the two passes *share one scope semantics*); Dep6 (every
> node *typed* for lowering) ≠ Dep8 (lowering *gated* on typing *succeeding*) — Dep6 is the type-annotation
> contract, Dep8 is the ordering/rejection gate; Dep9 (span *propagation*) ≠ Dep10 (error-*state* handoff).
> The two *IR-faithfulness* seams are likewise distinct: Dep11 (each source decl ↔ exactly one IR symbol, no
> dangling ref) is the *binding → IR-symbol* edge — distinct from Dep4 (which stops at the checker) and Dep7
> (IR-internal); Dep12 (the source type system maps totally/consistently onto the IR type system) is the
> *type-system correspondence* — distinct from Dep6 (annotations present, not re-inferred) and Dep7 (IR
> internally consistent given operands). **The anti-mock filter excludes nominal pairs** that share no
> truth-maker: e.g. lexer × codegen (the lexer and codegen never exchange an artifact directly — they couple
> only transitively, carried by Dep3/Dep9), and "parser × symbol table" beyond Dep2/Dep4 (the parser does not
> populate the symbol table — resolution does) are NOT direct seams and are correctly absent.

> **FM mapping for `Dep`.** A forgotten/violated `Dep` edge is an **FM-1** defect (a spanning integration
> criterion — the glue — not written / not covered; §4.2 FM-1 insufficiency, §18.10 *hole-i*) when it is a
> coverage hole, and an **FM-2** defect (criteria of two children incompatible / a relational defect at fixed
> composition; §4.2 FM-2) for the two-sided / shared-artifact seams whose breakage is a mutual-satisfiability
> conflict (Dep5 shared scope semantics, Dep10 error-state agreement, Dep11 decl↔symbol agreement, Dep12
> source↔IR type-system agreement). The §7 FM table records this. Per one-defect-one-place, a seam's failure
> is scored **here as a `Dep` item**, never re-listed as a separate criterion.

## 3. Authority `Del` — orthogonal note (NOT scored)

> **`Del` is the canon "who" axis** (§2.3: `Del: T → A`, exactly one agent per task) — **orthogonal** to the
> decomposition plane `{D, Dep, V}` and **NOT scored** as a decomposition item. This is a plane-separation
> note, NOT a NEGLECTED exclusion, NOT a criterion, NOT a completeness hole.

Who is *permitted* to invoke the compiler, approve a language change, or sign off the build, and any
segregation-of-duties over the toolchain, is **not** a predicate over the produced artifact (well-formed
code) and is **not** a decomposition node. A front-end can be perfectly correct (well-typed, position-
preserving, total) **and** have any authority model around it or none. Authority is a property of the
**delegation/ownership edges** (GFSO Issuer/Executor split, emergent from `Del`), not a component, seam,
invariant, edge-case, failure-mode, or scope-exclusion.

**Why authority is orthogonal (derived, not asserted).** A GFSO decomposition is graded on its
artifact-predicates and how the work splits ({D, Dep, V}) — predicates on *what must be true about the
produced artifact* and *how the work splits*. Access-control / approval / SoD over operating the toolchain is
**not** a predicate over the artifact: the produced code can be well-typed, position-preserving, total, and
deterministic **and still** have been built and signed off by the same person. In GFSO's primitives it is an
emergent property of the **edges of the delegation hierarchy**: the **Issuer** sets criteria and validates
`V`; the **Executor** produces (`Del` assigns who, and `V`-by-Issuer ≠ self-validation). It is emergent from
`Del` + the delegation hierarchy, not a node *within* the decomposition.

**Consequences for scoring (scorer rules):**
- A decomposer is **NOT penalized** for omitting any access-control / approval / SoD item — there is no
  decomposition slot it belongs in.
- **Force-fitting it into a criterion is a category error** (criterion = predicate on the produced code;
  authority = predicate on the process that operates the compiler). An agent who adds "only authorized users
  may run the compiler" earns no criterion-credit and loses none — a correct statement in a different plane.
- This is **plane-separation**, not a NEGLECTED scope-exclusion and not a completeness hole.

> **NB (in-plane vs orthogonal).** Language-level *visibility/access modifiers* — `private`, `public`, module
> visibility — ARE in-plane, part of D4 name resolution / D5 type-checking; they are *not* the authority
> plane. Only authorization/approval/SoD over *operating the toolchain* is orthogonal.

## 4. Criteria `V` — task predicates (former Invariants + Edge-cases + Failure-modes, COLLAPSED)

> `V` is **derived**: `V(t) = AND(criteria(t))` (§2.2, §3.1 Theorem 1). Every item below is a **predicate of
> the task** — a `criterion` whose conjunction is the validation. The former Invariants (pipeline-wide
> spanning predicates), Edge-cases (boundary-state predicates) and Failure-modes (defect-coupling predicates)
> are **all criteria** and are collapsed here into one section. Each criterion keeps its verbatim text +
> truth-maker and carries an **FM tag**: which canon failure mode(s) it precludes (§4.2 / §4.6). The old
> I/E/F labels are retired — the FM tag replaces them. (Item ids keep an I-/E-/F- prefix purely for
> cross-reference traceability to `reference_buckets_v1.md`; they are NOT separate categories.)

**How to read the FM tag.** Per §4.2/§4.6: a **spanning/coverage predicate** a faithful decomposition must
carry (and whose omission is a coverage hole) precludes **FM-1** (Correspondence — joint sufficiency); a
predicate enforcing **mutual satisfiability** of children / type-system or scope consistency across the
boundary precludes **FM-2** (Consistency); a predicate guarding against an **insensitive / mockable /
looks-OK-but-wrong** check (a value that passes where reality fails) precludes **FM-3** (Verifiability,
false-PASS); a predicate enforcing **correct fail-propagation / monotone preservation / termination of the
rule** precludes **FM-4** (Propagation).

### 4.1 Pipeline-wide spanning criteria (former Invariants)

A spanning criterion is a program-wide predicate that **spans passes** — no single pass establishes it; it
holds only if all the coupled passes are jointly correct (canon §2.2 joint sufficiency / §3.1). Canonicalized
by the *enforced predicate*, not by where it is checked (PLAN §1.3 rule 2). These are the binary correctness
conditions behind the goal `spec` ("the produced code is well-formed").

| # | Name | Enforced predicate | FM tag (precludes) | Truth-maker (covered iff the decomposition asserts…) |
|---|---|---|---|---|
| **V-I1** | **Every name resolved before use is typed (resolution completeness)** | At the end of resolution, every identifier use in a non-error program is bound to exactly one declaration (or a definite "unbound" error is raised) — no use reaches type-checking with a missing/ambiguous binding. | **FM-1** (spanning resolution-coverage predicate) | …that every name must be resolved (bound or definitively errored) before typing — no dangling/ambiguous binding survives into later passes. Spans D4, Dep4. Credit "every identifier is bound to its declaration / errors if not." |
| **V-I2** | **Every expression node is typed (typing completeness)** | At the end of type-checking, every expression (and sub-expression) node carries exactly one checked type, or the program is rejected — there is no untyped node in a program that proceeds to lowering. | **FM-1** (spanning typing-coverage predicate) | …that every expression must have a checked type before lowering (no untyped node proceeds) — the typing pass is total over the accepted program. Spans D5, Dep6. **Distinct from V-I3** (V-I2 = every *AST* node typed at the end of type-checking; V-I3 = every *IR* node well-typed after lowering). Credit "all nodes are typed / no untyped expression reaches IR." |
| **V-I3** | **Every IR node is well-typed / the IR is type-consistent (soundness through lowering)** | Every node of the generated IR is well-typed: each IR operation's operands and result types are consistent, and lowering *preserves* type-correctness — a well-typed source program lowers to a well-typed IR (no type information is lost or contradicted in translation). | **FM-1** (the headline soundness/well-formedness coverage predicate the `spec` names) + FM-2 (IR operand-type consistency) | …that the generated IR is well-typed / type-consistent (lowering preserves type-correctness; every IR node well-typed). The headline soundness invariant the `spec` ("well-formed produced code") names. Spans D6, Dep6, Dep7. Credit "the IR is well-typed," "lowering preserves types," "no ill-typed IR." **The central invariant of T08.** |
| **V-I4** | **Source positions preserved end-to-end (diagnostic locatability)** | Every artifact node (token, AST node, IR node) and every diagnostic carries a source position that traces back to the originating source span — at no pass boundary is the location lost, so every error/warning can name a real source location. (Includes, as a *soft* leg, the **positional correctness** of the computed line/column across newlines and tabs — an off-by-one or line/col drift is the finer correctness inside this invariant; scored softly, not double-penalized against the propagation predicate.) | **FM-1** (the diagnostics-locatability half of `spec`, spanning every pass) | …that source positions are preserved through *all* passes onto nodes and diagnostics (every error has a real source location). The diagnostics-quality invariant. Spans every pass; rests on Dep9. **Distinct from Dep9** (Dep9 = the per-edge *propagation contract*; V-I4 = the global predicate *no position is ever lost*). Credit "every diagnostic points to the right source location end-to-end"; an explicit "line/column computed correctly across newlines/tabs (no off-by-one)" earns the soft positional-correctness leg. |
| **V-I5** | **No pass invalidates an invariant established by an earlier pass (monotone invariant preservation)** | Each later pass *preserves* the guarantees earlier passes established — lowering does not un-resolve a name or strip a type; codegen does not violate the IR's type-consistency. An invariant once established (names bound, nodes typed, IR well-formed) holds through to the output. | **FM-4** (monotone preservation: later passes must not undo a prior guarantee — correct propagation of established invariants through the rule) | …that no later pass breaks an invariant an earlier pass established (lowering keeps things typed/resolved; codegen keeps the IR's guarantees) — the pipeline is invariant-monotone. The cross-cutting "no pass undoes a prior pass" condition the §2.2 bar names. Spans D5–D7, Dep6–Dep8. **Distinct from V-I3** (V-I3 = *the IR is* well-typed; V-I5 = *no downstream pass undoes* any established invariant, of which well-typedness is one). Credit "later passes preserve earlier guarantees," "lowering/codegen don't break type-correctness." |
| **V-I6** | **No accepted construct is silently dropped (end-to-end construct coverage / totality)** | Every construct the parser accepts is handled (resolved, typed, lowered, code-generated) — for every valid program the front-end produces complete output, with no construct silently skipped by a missing case. The pipeline is *total* over the accepted language. | **FM-1** (construct-coverage / totality — a spanning joint-sufficiency predicate) | …that no syntactically-valid construct is silently dropped anywhere in the pipeline (the front-end is total over the accepted language; every accepted form produces output). The completeness invariant. Spans D2–D7, Dep3. **Distinct from V-I2/V-I3** (those are *type* soundness; V-I6 is *coverage* — a construct can be typed yet have no lowering case). Credit "every valid construct is fully compiled, nothing dropped." |
| **V-I7** | **Deterministic / reproducible output (run-to-run stability)** | A fixed input produces **byte-identical** artifacts (tokens, AST, IR, target code) and an identical, position-sorted diagnostic sequence across runs — no dependence on hash-map iteration order, pointer/address values, timestamps, or environment. The pipeline is a pure function of its input. | **FM-1** (the reproducibility half of `spec` — a spanning predicate no single pass owns) | …that the front-end is deterministic / reproducible — the same source yields the same output and the same diagnostic order every run (no reliance on map/iteration order or addresses). The reproducibility invariant. Spans every pass (esp. symbol-table iteration → IR symbol order, and diagnostic ordering). Credit "deterministic output," "reproducible build," "diagnostics in a stable order." **Distinct from N (single-threaded)** — determinism of the *sequential* pipeline is a separate predicate from concurrency exclusion. |
| **V-I8** | **Error-state gating / fail-stop with non-zero exit (no swallowed error reaches success)** | Any error recorded by *any* pass (a) **blocks the passes that depend on its output** (an unparseable tree is not typed, an ill-typed program is not lowered — the Dep8 gate, generalized to every stage) and (b) **forces the front-end to terminate with a non-zero / failure status** — no program with a recorded diagnostic ever reaches a "success" exit. The error state is monotone: once set it is never cleared into a clean result. | **FM-4** (the pipeline-wide propagation predicate: any recorded fail must block dependents and propagate to the final AND-verdict) | …that a recorded error both blocks dependent downstream passes AND forces a failure result/exit (no error is silently swallowed so the driver reports success on a broken program). The fail-stop / error-state-monotonicity invariant. Spans the whole pipeline; generalizes the Dep8 ordering gate to the *process verdict*. Credit "any error makes the compile fail / exit non-zero," "a swallowed error must not let compilation report success," "error state is sticky." **Distinct from Dep8** (Dep8 = the *lower-only-after-semantics* edge between two passes; V-I8 = the *pipeline-wide* predicate that *any* recorded error blocks dependents and propagates to the final failure verdict). |

> **Criteria vs passes.** The invariant criteria are *spanning predicates*; the seams (`Dep`) are the *pass
> couplings* that must be right for the predicate to hold. They are scored separately (PLAN §1.3 rule 2): an
> agent asserting the predicate "the IR is well-typed" (V-I3) without naming the *typed-AST→lowering contract*
> (Dep6) has covered V-I3 not Dep6, and vice versa. The invariant criteria canonicalize by the enforced
> predicate (resolution-completeness ≠ typing-completeness ≠ IR-well-typedness ≠ position-preservation ≠
> invariant-monotonicity ≠ construct-coverage ≠ determinism ≠ error-state-gating — eight genuinely distinct
> predicates; a design can satisfy any subset and fail another). V-I7 (reproducibility) and V-I8 (fail-stop /
> non-zero exit) are pipeline-wide *process* predicates with no single-pass owner — V-I8 generalizes the Dep8
> *edge* into the *whole-pipeline verdict* (any recorded error blocks dependents and forces a failure exit),
> distinct from Dep8's single ordering edge.

### 4.2 Boundary-state criteria (former Edge-cases)

A boundary-state criterion is a boundary input/program a naive happy-path design silently mishandles — i.e. a
predicate the design must satisfy at the boundary, or the corresponding check is **insensitive** there
(passes a wrong result). Covered iff the decomposition names the same boundary condition and that it needs a
rule.

| # | Name | What it requires | FM tag (precludes) | Truth-maker (covered iff named) |
|---|---|---|---|---|
| **V-E1** | **Recursive / mutually-recursive types and functions (forward declaration / fix-point)** | A type that refers to itself (`list = nil | cons(int, list)`) or two declarations that refer to each other (`f` calls `g`, `g` calls `f`; type `A` contains `B`, `B` contains `A`): resolution must allow forward references within a recursive group, and type-checking must reach a fix-point without infinite recursion (recursion guard / collect declarations before checking bodies). | **FM-3** (a happy-path resolver/checker is insensitive to the cyclic group → mis-binds or non-terminates) | …recursive/mutually-recursive types or functions and that resolution/typing must handle the forward/cyclic reference (two-pass: declare then check, or a recursion guard). Credit "mutually recursive definitions," "self-referential types," "forward reference between functions." |
| **V-E2** | **Forward reference / use-before-declaration (declaration ordering) — and the decl-collection pre-pass contract** | A name used textually before its declaration (a top-level function or type referenced earlier in the file): resolution must (per the language's rules) hoist declarations / do a **declaration-collection pre-pass** so a legal forward use binds, while still rejecting a genuinely-unbound name. The pre-pass is also a **resolver↔checker contract**: the resolver implements a stated declaration-collection policy P (which scopes hoist) and the type-checker assumes exactly P when it looks up forward/recursive references — covering the seam form of GT20 (V-E1's recursive groups rest on the same pre-pass). | **FM-3** (insensitive to a legal forward use → false-FAIL) + FM-2 (resolver/checker must agree on the same collection policy P) | …the use-before-declaration / forward-reference boundary and a rule (declaration pre-pass / hoisting) that binds legal forward uses, with the resolver and checker agreeing on the same collection policy. Credit "use a name before it's declared," "two-pass resolution: collect declarations then check bodies," "declaration pre-pass." Distinct from V-E1 (V-E1 = *cyclic* definitions; V-E2 = *ordering* of an acyclic forward use — both rest on the pre-pass). |
| **V-E3** | **Shadowing across scopes vs duplicate declaration in the *same* scope** | Two distinct boundaries: (a) **shadowing** — a name redeclared in an inner scope hiding an outer one (a local shadowing a global/parameter, a loop var shadowing an outer): resolution must bind each use to the *nearest* enclosing declaration and the scope boundary must not leak an inner binding outward; (b) **same-scope re-declaration** — *two* declarations of the same name in *one* scope, which (unlike shadowing) is a **duplicate-declaration error**, not a legal hide. The boundary is distinguishing "inner hides outer" (OK) from "declared twice here" (error). | **FM-3** (a naive resolver silently mis-binds shadowing / fails to flag duplicate decl → passes wrong) | …both the shadowing boundary (a use binds to the innermost matching declaration; nearest wins) **and** the same-scope-redeclaration boundary (declaring the same name twice in one scope is a duplicate-decl error, distinct from shadowing). Credit "variable shadowing / inner hides outer" for (a) and "duplicate declaration in the same scope is an error" for (b) — they are *different diagnoses* (legal hide vs hard error). |
| **V-E4** | **Empty program / trivial program** | A program with no declarations, an empty file, or a single trivial statement: every pass must produce a defined (empty-but-valid) artifact, not crash on an empty token stream / empty AST / empty IR. The degenerate input is the boundary. | **FM-3** (the degenerate-input check is insensitive — a happy-path pass crashes instead of passing the empty case) | …the empty/trivial-program boundary and that the pipeline handles it cleanly (empty input → valid empty output, no crash). Credit "empty program," "no input," "a program with nothing in it." |
| **V-E5** | **Deeply nested expressions / deep recursion (parser & checker depth limit)** | A very deeply nested expression or block (thousands of parentheses, deep `if/else`): a recursive-descent parser or recursive type-checker can stack-overflow; the design must bound recursion depth (explicit stack / iterative walk / a depth limit with a clean error) rather than crash. | **FM-3** (happy-path recursion is insensitive to depth → crashes instead of a clean diagnostic) | …the deeply-nested-input boundary and that recursion depth must be bounded / handled (iterative walk or a clean depth-limit error, not a stack overflow). Credit "deeply nested expressions," "recursion-depth limit," "avoid stack overflow on deep input." |
| **V-E6** | **Error-containing input (the lexer/parser/semantic error paths)** | Input that does *not* compile — an invalid character, an unterminated string/comment, a syntax error, an unbound name, a type error: each pass must produce a *diagnostic and a defined recovery state* (Dep10), not a crash, and the overall front-end must reject the program cleanly with a useful error. **Lexer-specific recoverable boundaries** belong here as concrete instances: a string/char literal with an unterminated body or a bad/over-long escape (decode-or-diagnose, span anchored at the opening quote), and a comment that is unterminated at EOF or whose nesting policy must be stated (nested vs flat) — each reported and recovered, not crashed on. This is the non-happy-path boundary that the whole error machinery exists for. | **FM-3** (a happy-path pass is insensitive to the erroring boundary input — crashes / mishandles instead of diagnosing) | …that the pipeline must handle invalid/erroring input at each level (lex error incl. unterminated/badly-escaped string-or-comment, syntax error, name error, type error) by reporting and recovering, not crashing. Credit "handle invalid input," "report errors gracefully," "an unterminated string/comment / bad escape / bad token / type error must produce a diagnostic and recover." Distinct from Dep10 (Dep10 = the *inter-pass handoff* of the error; V-E6 = the *boundary input class* that must be handled at all). |
| **V-E7** | **Literal value / limits (value parsed once, range-checked, carried unchanged)** | Integer and float literals (and their bases/separators/special forms) must be parsed to a **defined representation/width** *once*, **range-validated at the checker** against the target type, and the resulting value carried **unchanged** to the IR — never re-parsed or truncated at IR-gen, and an out-of-range or malformed literal **diagnosed**, never silently wrapped/rounded. The boundary is the literal whose textual form is legal but whose *value* exceeds the type's range. | **FM-3** (a value check insensitive to an out-of-range/overflowing literal silently wraps → false-PASS) | …the literal-value / numeric-limit boundary and that a literal's *value* (not just its lexeme) is parsed once to a defined representation, range-checked at the checker, and carried unchanged to IR (out-of-range/overflowing literals diagnosed, not silently wrapped). Credit "integer/float literal out of range," "literal overflow must error," "the literal's value is fixed once and not re-parsed." Distinct from D1 (D1 = lex the *lexeme*; V-E7 = the *value*'s representation/range/carry). |
| **V-E8** | **Encoding / Unicode at the lexer (BOM, line endings, codepoint vs byte offset)** | The lexer must handle the source's text encoding per a stated policy: a leading **BOM** consumed (not lexed as an identifier/junk), **CRLF vs LF** counted consistently for line numbers, identifier-character classes defined over codepoints per the policy, and **byte-offset vs codepoint-offset** kept consistent so spans (Dep9/V-I4) point at the right column. The boundary is non-ASCII / mixed-line-ending source. | **FM-3** (an offset/line-count check insensitive to BOM/CRLF/codepoint drift yields a wrong-but-passing span) + FM-2 (byte-vs-codepoint offset must stay consistent with the span artifact) | …the encoding/Unicode lexer boundary and that BOM, CRLF/LF line counting, and byte-vs-codepoint offsets are handled by a stated rule (so spans stay correct). Credit "handle Unicode/UTF-8 source," "BOM / CRLF handling," "codepoint vs byte offsets for columns." A real lexer boundary with a position-correctness coupling into Dep9/V-I4. |
| **V-E9** | **Empty constructs (empty body / params / record / array, not just empty program)** | Degenerate *constructs* inside an otherwise non-empty program — an empty function/block body, an empty parameter list, an empty record/struct/array/tuple literal, a zero-field type — must parse, resolve, type, lower and codegen to a defined (empty-but-valid) artifact, not hit a special-case crash or a "≥1 element" assumption. Distinct from V-E4 (V-E4 = the empty *program/file*; V-E9 = an empty *construct* within a real program). | **FM-3** (a "≥1 element" happy-path assumption is insensitive to a zero-element construct → crash / wrong) | …the empty-*construct* boundary (empty body / empty param list / empty record / empty array) and that each is handled without a special-case crash or a min-one-element assumption. Credit "empty function body," "no parameters," "empty record/array," "zero-element construct." Distinct from V-E4 (empty whole program) — a different boundary with different breakage. |

### 4.3 Defect-coupling criteria (former Failure-modes — only those with NO `Dep` twin)

Phrased as **concrete coverable claims** (PLAN §1.3 rule 4), never adjectives. Each names a specific defect
coupling AND its resolution; covered iff the decomposition names the same coupling and a guard.
**One-defect-one-place (PLAN §1.3 rule 1):** a defect-coupling is kept here ONLY if it has **no `Dep`-seam or
invariant-criterion twin**. A defect that shares the *same pair, same falsifier, same fix* as an existing
seam/invariant is **not** a separate item — the seam/invariant already carries it. The §2.2-bar's
illustrative failures are **deliberately NOT listed** because they are already carried: *ill-typed IR
escapes* = V-I3/Dep8, *IR generated from an un-typechecked node* = Dep8, *lost source location → useless
diagnostic* = V-I4/Dep9, *scope resolved wrong* = Dep5/V-E3, *a construct handled in parse but dropped before
codegen* = V-I6/Dep3, *parser accepts an ill-typed program because a contract was loose* = Dep8 (a parser is
not supposed to type-check; the gate is the seam). What remains here are couplings with **no** seam/invariant
twin, each pinned to a canon §4 FM class.

| # | Name | FM tag (precludes) | What it requires (coupling + guard) | Truth-maker (covered iff named with a guard) |
|---|---|---|---|---|
| **V-F1** | **Error cascade / spurious-error flood (one real error → many fake ones)** | **FM-4** (propagation) | A single early error (one syntax error, one unbound name) makes a naive pipeline emit a *cascade* of secondary errors as later passes trip over the broken state — burying the real error and producing a useless error report. **No `Dep`-twin** (Dep10 is the *mechanism* of error handoff; V-F1 is the *flood failure* — the residual that even a recovery scheme can produce if it re-reports derived errors). Guard: error de-duplication / suppress errors derived from a poisoned node / cap the count and point at the root cause. | …that one error must not cause a flood of spurious secondary errors AND a guard (suppress errors from already-erroring nodes, de-dup, report the root cause). Credit "don't emit cascading/derived errors," "suppress secondary errors," "the first error shouldn't trigger ten fake ones." Distinct from Dep10 (recovery *handoff*) — V-F1 is the *flood-suppression* guard on top of it. |
| **V-F2** | **Silently-accepted-but-wrong: a loose contract passes an ill-formed program (false PASS)** | **FM-3** false-PASS | A pass *appears* to validate (it runs, raises no error) but its contract is loose enough that an ill-formed program slips through and produces wrong output that *looks* well-formed — e.g. an incomplete type rule that misses one ill-typed combination, so codegen happily emits wrong code while every check says "OK." "The checker ran and passed" does NOT prove "the program is well-typed." **No `Dep`-twin** (Dep6/Dep8/V-I3 are the *mechanism/predicate*; V-F2 is the *false-PASS residual* — a present-but-insensitive check). Guard: an independent IR-level verification pass (a typed-IR verifier / assertions on IR well-formedness) that re-checks the output rather than trusting each pass's self-report. | …that a pass can *appear* to succeed yet pass an ill-formed program through (an incomplete/loose check), AND a backstop (an independent IR verifier / re-check of the output beyond "the pass ran"). Credit any concrete "a check can silently miss and an independent verifier is needed" — **no GFSO vocabulary required**. **Mirrors the GFSO faithfulness residual** (Ст. III.1) — the hardest to articulate. |
| **V-F3** | **Missing-case fallthrough: an unhandled construct hits a default branch that drops/mis-compiles it** | **FM-1** (insufficiency, at a pass) | When a new/uncommon node kind reaches a pass whose `switch`/visitor has no case for it, a permissive default branch (no-op, "return null", a catch-all) *silently* drops or mis-compiles it instead of failing loudly. **Distinct from V-I6/Dep3** (those assert the *property* "no construct dropped"; V-F3 is the concrete *coding-pattern coupling* — the permissive default that *causes* a silent drop, plus the guard against it). Guard: exhaustive case-matching / a non-exhaustiveness check / an explicit `unreachable`-with-error default so an unhandled kind is a hard error, not a silent skip. | …that an unhandled node-kind must fail loudly, not fall through a permissive default that silently drops it, AND a guard (exhaustive match / compiler-enforced exhaustiveness / explicit error default). Credit "exhaustive switch over node kinds," "fail on an unknown node, don't default-skip," "non-exhaustive match check." Distinct from V-I6 (the *property*) — V-F3 is the *exhaustiveness-enforcement* mechanism. |
| **V-F4** | **Lexer no-progress: a step that consumes no input spins forever** | **FM-4** (propagation / non-termination) | On an unexpected or invalid character the lexer's main loop can fail to advance the cursor — emitting nothing and re-reading the same position — and **spin forever** (or stall) instead of terminating. **No `Dep`-twin** (this is not maximal-munch Dep1, which is about *which* token; nor error-recovery Dep10, which is the *handoff* of an already-formed error — V-F4 is the *progress* guarantee of the lexer loop itself). Guard: every lexer step consumes ≥1 character or emits an explicit error token and advances — a no-progress assertion / invariant that the cursor strictly increases. | …that the lexer must make progress on every step (consume ≥1 char or emit an error token and advance) so an invalid/unexpected character can never cause an infinite loop or stall, AND the guard (a strict-advance / no-progress assertion). Credit "the lexer always advances," "no infinite loop on a bad character," "consume-or-error-and-advance." Distinct from Dep1 (which token) and Dep10 (error handoff) — V-F4 is *termination/progress* of the scanner. |

> **Defect-coupling discipline.** Only four defect-coupling criteria survive because T08 is *seam-and-invariant
> dense*: most concrete failures ARE the negation of an exact contract (`Dep`) or invariant criterion and are
> scored there, not double-counted (PLAN §0 residual: F-vs-X double-counting flagged — enforced here). V-F1
> (error cascade flood), V-F2 (loose-check false-PASS), V-F3 (permissive-default silent drop), V-F4 (lexer
> no-progress / non-termination) are the couplings with **no** twin: a different trigger (one-error-to-many;
> an *insensitive present* check; a catch-all default *pattern*; a *non-advancing* scanner step) than any
> single contract seam. V-F4 is a *progress/termination* failure (FM-4) distinct from both maximal-munch Dep1
> (which token) and error-handoff Dep10 (already-formed error). FM-2 (incompatible child criteria) is carried
> by the contract seams; FM-5 (stale spec) and FM-6 ("D not determinable at start") do not arise — the passes
> are fully determinable from the spec, and the source language is fixed (N3). FM-7 (no feedback channel) is
> in-band: the diagnostics channel (V-I4/Dep9) is the front-end's feedback path and is already a
> criterion/seam (see §7).

## 5. NEGLECTED — declared scope-exclusions (each with its `predictability_verdict`, STD-1/2/3)

> Canon §5.1 STD-1: a decomposition **without** NEGLECTED is incomplete by definition — the auditable "no
> silent skip" record. Each entry carries a **`predictability_verdict`** (STD-2 §5.2: predictability is
> presumed; the *declarer* bears the burden of proving safe-to-skip) and an `invalidation_condition` (when the
> exclusion flips in-scope). Only assumptions/exclusions whose **omission would otherwise be a foreseeable
> defect** (FM-1.b, §5.2 / §4.2: a predictable external risk left without a mitigating child) — assessed-and-
> declared-skipped, not a dumping ground (PLAN §0 N-inflation caution): an exclusion is listed only if omitting
> it makes an *out-of-scope* concern look like a front-end-logic defect, OR if the task statement explicitly
> bounds it.

| # | Excluded assumption | `predictability_verdict` (why safely excluded) | Truth-maker (covered iff the decomposition declares…) |
|---|---|---|---|
| **N1** | **Optimization passes are out of scope** | The task is the *front-end correctness* pipeline (lex→…→codegen producing *well-formed* code), not an optimizing compiler. Constant folding, inlining, dead-code elimination, loop optimization, peephole — all are correctness-preserving transforms layered *after* a correct front-end. Declared boundary: absence of optimization is not a front-end defect (the produced code is well-formed, just not fast). Invalidation: if an optimization pass is added, it joins as another pass that must obey V-I5 (preserve type-correctness / semantics). | …that optimization / optimization passes are out of scope (the front-end produces correct, not optimized, code). |
| **N2** | **Full target back-end (register allocation, instruction scheduling, ABI realization) is out of scope** | Codegen here is the *structural* lowering of IR to a target form (the front-end's hand-off); register allocation, instruction selection/scheduling, calling-convention/ABI realization, and target-machine encoding are the *back-end's* concern. Declared boundary: a missing register allocator is not a front-end bug. Invalidation: if real target-machine code is required, the back-end concerns become in-scope as downstream passes. | …that full target codegen / register allocation / instruction scheduling / ABI is out of scope (codegen is the structural IR→target hand-off, not a full back-end). |

## 6. Hardest / most-easily-forgotten seams (flag for scorer)

> Not a category — a scorer pointer at the highest-signal `Dep` edges.

- **Dep8 — semantic-checks-complete-before-lowering (the soundness gate).** The single most-forgotten seam
  *as an explicit edge*: agents name "type-check" and "lower to IR" as components but drop the *ordering
  contract* that an ill-typed program must be **rejected, not lowered**. Its absence is exactly the §2.2-bar
  "IR generated from an un-typechecked node / parser accepts an ill-typed program" failure.
- **Dep9 — source-position propagation threaded through every stage.** Spans/locations are attached at the
  lexer and routinely dropped at a later pass boundary; the result is a diagnostic that can't point at the
  source. The classic forgotten cross-stage contract (the per-edge form of invariant V-I4).
- **Dep3 — no accepted construct dropped (end-to-end coverage).** The contract that the set of node kinds the
  parser produces ⊆ the set every later pass handles — a construct parsed but with no lowering/codegen case
  is a parse-but-don't-emit gap, the §2.2-bar "handled in parse but dropped before codegen" failure.
- **Dep5 — shared scope/shadowing semantics between resolver and type-checker.** Distinct from "bindings
  exist" (Dep4): the two passes must agree on *one* scope/shadowing model, or shadowing/capture lets a use
  see the wrong declaration's type. Easily collapsed into Dep4 and lost.
- **Dep11 — symbol-allocation (decl ↔ one IR symbol, no dangling ref).** Agents name "resolve names" and
  "lower to IR" but drop the *binding-carried-into-IR* edge: that each declaration becomes exactly one IR slot
  all its uses share. A collapsed/duplicated/dangling IR symbol is a real codegen bug agents assume away.
- **Dep12 — type-system consistency across the checker→IR boundary.** Agents name "lower the typed tree"
  (Dep6) but drop the assertion that the *IR type system can actually represent* every checker-legal type and
  coercion (a total `lowerType`, legal IR conversions, agreeing assignability). The seam that makes source and
  IR type systems faithful images — forgotten because "it's already typed" is mistaken for "it has an IR
  type."

## Appendix — settled adjudications carried over (scorer must apply; verbatim from `reference_buckets_v1.md`)

- **Dep4 vs Dep5.** Kept separate (bindings *exist and are complete* vs the two passes *share one
  scope/shadowing semantics*). On a simple language with trivial scoping these nearly coincide. If an agent
  writes one "the type checker uses the resolved scopes" point, the scorer should credit **one** and treat the
  other as a non-redundancy merge, **not** two coverage holes. Auditor: confirm this is a true two-truth-maker
  split (I believe it is — completeness-of-binding vs agreement-on-scope-model are different bugs) or fold to
  one `Dep`.
- **Dep6 vs Dep8.** Close: Dep6 = lowering needs every node *typed*; Dep8 = lowering is *gated* on type-
  checking *succeeding*. Scored separately (the type-annotation contract vs the ordering/rejection gate — a
  program could be fully typed yet a buggy pipeline still lowers a node that failed a *different* semantic
  check). Auditor: confirm this is the intended annotation-vs-gate split and not a hidden double-count; on a
  pipeline where "typed" ⟺ "type-check passed" they may collapse — flagged. (Dep8 is **not** auto-granted by a
  Dep6 mention.)
- **V-I3 vs V-I5.** V-I3 (the IR is well-typed) is one *instance* of V-I5 (no pass undoes any prior invariant).
  Kept distinct because V-I3 is the headline *soundness* predicate the `spec` names explicitly, while V-I5 is
  the general monotonicity condition (covering also position-preservation, resolution). Auditor: if scored only
  on type-soundness, V-I3 may be read as subsumed by V-I5 — flagged; the headline IR-well-typedness deserves
  its own item.
- **V-F2 (loose-check false-PASS) decidability / down-weight.** This is the GFSO faithfulness-residual analogue
  (Ст. III.1) and the *softest* item (PLAN §0 decidability-bimodality caution). It is phrased as a concrete
  coupling (an insensitive present check + a named independent IR-verifier backstop), but the auditor should
  weight its coverage as noisier signal than the hard-binary `Dep`-contracts (down-weight ~0.5).

  a real artifact the `Dep`-seams are predicates on. Some decompositions fold the data model into the

  whether D3 should instead be a note on D2 rather than a standalone component (fold-credit allowed).
